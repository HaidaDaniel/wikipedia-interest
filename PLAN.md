# Plan: Wikipedia Interest Agent Skill

## Goal

Turn a fuzzy audience-research question into a reproducible, conservative signal from Wikimedia Pageviews. The agent handles intent and explanation; this package handles article resolution, retrieval, statistics, visualisation and artifacts.

## Architecture and data flow

```text
natural language -> agent maps request to CLI arguments
                 -> resolver (MediaWiki search + langlinks)
                 -> Wikimedia Pageviews API (cached)
                 -> normalized time series
                 -> deterministic metrics / anomalies / evidence quality
                 -> result.json + chart.png + optional report.pdf
                 -> agent explains signal and caveats
```

Modules are deliberately direct: `wikipedia.py` owns HTTP, `resolver.py` owns article identity, `cache.py` owns JSON cache, `analysis.py` owns all calculations, `reliability.py` owns scoring, `charts.py` and `report.py` own artifacts, and `runs.py` owns reproducibility.

## LLM/code boundary

The agent may infer topic, languages, dates and a decision criterion from natural language. It must not write analysis code, inspect raw CSV rows, choose formulas, or claim market size. It calls `analyze`, reads compact JSON, and uses `inspect-run` for follow-ups. Every metric and label is generated by deterministic code.

## Main entities

- `AnalysisRequest`: topic, language codes, inclusive date range, granularity and criterion.
- `ResolvedArticle`: project, title, URL, method, confidence and warnings.
- `PageviewPoint`: timestamp, views and source metadata.
- `SeriesAnalysis`: aggregated observations, metrics, anomalies and evidence quality.
- `Run`: request, resolved articles, result and artifact paths.

## CLI contract

`wikipedia-interest analyze --topic TOPIC --languages pl,cs --start 2024-09 --end 2026-09 --granularity auto --output output`

Stdout is one JSON object and stderr contains human-readable operational errors only. `report --run output/RUN_ID` adds a one-page PDF. `inspect-run output/RUN_ID` emits a compact summary. `analyze --from-run output/RUN_ID` reuses the prior request and cache while allowing request flags to override it.

## Cache and persistence

Cache entries live in `.cache/` and are keyed by endpoint inputs, project, article, access, agent, granularity and dates. A cache hit avoids network access; there is a `--no-cache` escape hatch. A run is `output/<UTC timestamp>-<short hash>/` containing request, metadata, full result, normalized CSV, normalized pageviews JSON and chart. `pageviews.json` is intentionally named as normalized data, not claimed to be an untouched API payload. Generated output is ignored by git except the directory marker.

## Resolution

The resolver searches English Wikipedia once for a canonical topic, requests its interlanguage links, and selects the exact target language link. Wikidata is queried only when requested languages are missing from langlinks. It falls back to a target-language search only when necessary. Exact/linked matches are high/medium confidence; weak lexical matches and Wikipedia disambiguation pages are low-confidence candidates with explicit warnings. Top target-language search matches are also low-confidence candidates, and low-confidence candidates are excluded from comparison rankings. Unresolved languages are explicit errors rather than silent substitutions.

## Statistical methodology

Monthly is the default for spans over 180 days; daily is used for shorter spans. The current incomplete period is excluded. Missing expected periods remain null/gapped for plotting and are excluded from calculations. Metrics include robust level statistics, first-vs-last window growth, 12-period YoY where possible, log-linear annualized trend, smoothed trend, volatility, completeness and robust spike detection. Trend labels use documented thresholds, not an LLM judgement. Analyze stdout is compact; full observations remain in `result.json` and can be requested with `--verbose-json`.

## Reliability methodology

`reliability` is evidence quality, not a confidence interval. A transparent 0–100 score rewards sufficient length, completeness, effect size, trend fit, low noise and strong resolution; it penalizes missing data and anomalies. `high` is 70+, `medium` 45–69, `low` below 45. Reasons are returned with every series.

## PDF and testing

Matplotlib creates both the chart and a single-page PDF without a browser. Unit tests use synthetic data and mocked HTTP responses. A manual integration command exercises real Wikimedia endpoints; tests never require dozens of live calls.

## Limitations and next stages

Pageviews are attention, not willingness to pay. Cross-language absolute counts are not market size. One article may underrepresent a concept, and events, seasonality, bots and coverage differences remain. Future phases: topic groups, Wikidata concept graphs, normalized audience signals, external validation sources, event annotation, batch ranking and backtesting against product outcomes.
